# Invoice App: Project Plan

**Scope:** Local-only, Android-only, personal build (not released). No backend, no network, no store listing.

---

## 1. Goals and Constraints

| Item | Decision |
|---|---|
| Platform | Android only (phone, 8" and 10" tablets) |
| Data | 100% on-device, encrypted at rest |
| Network | None. `INTERNET` permission blocked in release builds |
| Distribution | Sideloaded APK. No Play Console, AAB, Play Integrity or `eas submit` |
| Design | Monochrome (black / white / grey), 48dp touch targets |
| Out of scope | Domain core (invoice numbering, integer-money maths, schema and migrations). Removed from this plan |

---

## 2. Tech Stack

| Layer | Choice | Notes |
|---|---|---|
| Client | React Native + Expo (SDK 52+, newest stable), CNG, `expo-dev-client` | `android/` is generated by prebuild and never committed |
| Language | TypeScript, `strict`, `noUncheckedIndexedAccess` | |
| Build | `eas build --profile preview` (APK) or `eas build --local` | Keep one release keystore. Losing it blocks in-place updates |
| Persistence | `expo-sqlite` (WAL) + SQLCipher via config plugin | SQLCipher 4 uses AES-256-CBC with per-page HMAC-SHA512 (not GCM) |
| Key storage | 32 random bytes in `expo-secure-store` (Android Keystore) | |
| PDF | `expo-print` `printToFileAsync`, HTML template, base64 `@font-face` TTF | Vector output, Unicode-safe |
| Excel | `exceljs` with batched reads and `writeBuffer()` to file via `expo-file-system` | Streaming writer needs Node streams, so avoid it. Needs a `buffer` polyfill. Cap rows per sheet |
| UI | Monochrome tokens, 48dp targets | Exceeds the 44pt target |

## 3. Project Setup

### app.json

```json
{
  "expo": {
    "orientation": "default",
    "android": {
      "allowBackup": false,
      "blockedPermissions": [
        "android.permission.INTERNET",
        "android.permission.ACCESS_NETWORK_STATE"
      ]
    },
    "plugins": [
      ["expo-sqlite", { "useSQLCipher": true }],
      "expo-secure-store"
    ]
  }
}
```

- Keep `INTERNET` **out of the dev-client profile**, since Metro needs it. Block it only in the preview/release profile.
- `allowBackup: false` is needed because a Keystore key will not restore on another device.
- Backup path: in-app encrypted export / import.

### Database open (src/data/db.ts)

```ts
import * as SQLite from 'expo-sqlite';
import * as SecureStore from 'expo-secure-store';
import * as Crypto from 'expo-crypto';

const KEY_NAME = 'db_key_v1';

async function getKeyHex(): Promise<string> {
  let k = await SecureStore.getItemAsync(KEY_NAME);
  if (!k) {
    const bytes = await Crypto.getRandomBytesAsync(32);
    k = Array.from(bytes, b => b.toString(16).padStart(2, '0')).join('');
    await SecureStore.setItemAsync(KEY_NAME, k, {
      keychainAccessible: SecureStore.WHEN_UNLOCKED_THIS_DEVICE_ONLY,
    });
  }
  return k;
}

export async function openDb() {
  const db = await SQLite.openDatabaseAsync('invoices.db');
  await db.execAsync(`PRAGMA key = "x'${await getKeyHex()}'";`); // must be first
  await db.execAsync('PRAGMA journal_mode = WAL; PRAGMA foreign_keys = ON;');
  return db;
}
```

## 5. Responsive Design

Widths are window width in dp (via `useWindowDimensions`), so split-screen and foldables work.

| # | Token | Width (dp) | Typical device | Columns | Panes | Nav |
|---|---|---|---|---|---|---|
| 1 | `xs` | 0-359 | Small phone | 4 | 1 | Bottom tabs |
| 2 | `sm` | 360-599 | Standard phone | 4 | 1 | Bottom tabs |
| 3 | `md` | 600-767 | 8" portrait | 8 | 1-2 | Navigation rail |
| 4 | `lg` | 768-959 | 10" portrait | 8 | 2 | Navigation rail |
| 5 | `xl` | 960-1199 | 8" landscape | 12 | 2-3 | Rail (labels) |
| 6 | `xxl` | 1200+ | 10" landscape | 12 | 3 | Rail (labels) |

```ts
// src/ui/useBreakpoint.ts
import { useMemo } from 'react';
import { useWindowDimensions } from 'react-native';

export type BP = 'xs' | 'sm' | 'md' | 'lg' | 'xl' | 'xxl';

const STEPS: ReadonlyArray<readonly [BP, number]> = [
  ['xxl', 1200], ['xl', 960], ['lg', 768], ['md', 600], ['sm', 360], ['xs', 0],
];

const META: Record<BP, { columns: 4 | 8 | 12; panes: 1 | 2 | 3; gutter: number; margin: number }> = {
  xs:  { columns: 4,  panes: 1, gutter: 12, margin: 16 },
  sm:  { columns: 4,  panes: 1, gutter: 16, margin: 16 },
  md:  { columns: 8,  panes: 2, gutter: 16, margin: 24 },
  lg:  { columns: 8,  panes: 2, gutter: 20, margin: 24 },
  xl:  { columns: 12, panes: 3, gutter: 24, margin: 32 },
  xxl: { columns: 12, panes: 3, gutter: 24, margin: 32 },
};

export function useBreakpoint() {
  const { width, height } = useWindowDimensions();
  return useMemo(() => {
    const bp = STEPS.find(([, min]) => width >= min)![0];
    return {
      bp, width, height,
      ...META[bp],
      isLandscape: width > height,
      isPhone: bp === 'xs' || bp === 'sm',
      isTablet: bp !== 'xs' && bp !== 'sm',
      atLeast: (min: BP) => width >= STEPS.find(([k]) => k === min)![1],
    };
  }, [width, height]);
}
```

## 7. UX Rules

1. **48dp minimum touch target, 8dp spacing between targets.** On tablets, enlarge the hit area, not the glyph.
2. **Layout changes by pane count, not by scaling.** Add panes at md/lg/xl and cap reading width at about 720dp.
3. **State survives resizing.** The draft invoice lives in one store. Autosave drafts to SQLite on field blur.
4. **Monochrome hierarchy** through weight, size, borders and fill. Status uses glyph + text: ● Paid, ◐ Partial, ○ Draft, ✕ Void.
5. **Numbers are tabular and right-aligned.** Show currency once in the header and align line totals in one column.
6. **Reversible destructive actions.** Void instead of delete, "Undo" snackbars, confirm step only for backup restore. The totals bar stays above the keyboard.

## 9. Export Plan

**PDF**
- HTML template with embedded base64 TTF via `@font-face`.
- `printToFileAsync` writes a vector PDF. Share via the Android share sheet.
- Page sizes: A4 and Letter.

**Excel**
- One sheet per export, batched reads from SQLite.
- Cap rows per sheet, release buffers between batches.
- `writeBuffer()` then save with `expo-file-system`.

**Backup**
- Encrypted export / import of the database file from within the app.
- Confirmation step on restore only.

## 12. Risks and Notes

| Risk | Mitigation |
|---|---|
| Lost keystore | Back it up somewhere safe. In-place updates depend on it |
| Lost DB key (uninstall or new device) | Data is unrecoverable by design. Use the encrypted export as backup |
| exceljs memory on large exports | Batching, row caps, one sheet per export |
| Metro needs `INTERNET` | Only block it in non-dev-client builds |
| Money and numbering logic now unspecified | Decide where this lives before Phase 4. Floating-point money can cause rounding errors on totals |
