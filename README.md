# Invoice ERP — Android app (standalone)

Offline, local-only invoicing app for a garment business: invoices with party snapshot,
products by name × size with live Sold / Available stock and a restock ledger, payments,
PDF + Excel export, and SQLCipher-encrypted storage with on-device backups. The app opens behind
a PIN lock (4–6 digits, optional fingerprint / face unlock, a recovery code for a forgotten PIN).
Android only.

This folder is **self-contained**: copy it anywhere, open it in your editor, and build or run
it from here. It does not depend on the `digital-invoice` desktop workspace.

## Tech stack

| Layer | Choice |
| --- | --- |
| Framework | React Native 0.88 + Expo SDK 58 (CNG, `expo-dev-client`) |
| Language | TypeScript strict (`noUncheckedIndexedAccess`) |
| Database | `expo-sqlite` with SQLCipher; key in Android Keystore via `expo-secure-store` |
| App lock | PIN + recovery code as salted SHA-256 in `expo-secure-store` (`expo-crypto`), fingerprint / face via `expo-local-authentication`; S7 screen in `src/features/auth/`, logic in `src/auth/` |
| Money | Integer paise everywhere; ISO-8601 dates |
| Documents | PDF via `expo-print` HTML template; XLSX via the in-house `src/export/xlsxWriter.ts` (no exceljs) |
| UI | **Flat Glass · Brand Blue** design kit (`design/DESIGN.md`, rules in `CLAUDE.md`) built as components in `src/ui/`: 5-colour theme + glass recipes in `tokens.ts`, flat headers, glass cards, floating bottom nav / rail, segmented controls, Feather line icons, a 3D pie chart (`react-native-svg`), light and dark (Sign In) themes, Android Back handling |
| Fonts | Inter for text (4 weights) and Bebas Neue for displayed numbers, both SIL OFL 1.1, via `@expo-google-fonts/*` + `expo-font`; the invoice PDF embeds subsets generated into `src/export/pdfFonts.ts` |
| Layout | 6 breakpoints: bottom tabs on phones, rail + 2–3 panes on tablets |
| Packaging | Local Gradle (no cloud needed); optional EAS profiles in `eas.json` |

## Copying this folder somewhere new

**Don't copy it with Explorer copy/paste.** Building the app makes Gradle write caches
inside `node_modules` and `android/` with paths up to ~410 characters
(e.g. `node_modules\expo-modules-core\android\build\.transforms\…`). Explorer stops at
**260**, even with Windows long paths enabled, and fails with "file name too long".

Use the copy script. It leaves those caches behind; they're regenerated by the next build:

```bash
powershell -ExecutionPolicy Bypass -File scripts/copy-project.ps1 -Destination C:/Projects/INV-MOBILE-APP
```

- Copies everything else, including `node_modules`, so no internet is needed.
  Add `-FreshInstall` to skip `node_modules` and run `npm ci` at the destination instead.
- Refuses a non-empty destination, and reports the longest path it produced.
- Keep the destination short, like `C:\Projects\INV-MOBILE-APP`. After the copy, the longest file
  is ~200 characters relative to the folder, so the folder path itself must stay under ~60 characters.
- Then build (next section). The first build at the new place takes about 2 minutes.

Already copied, or the copy failed partway? In the copied folder, run
`scripts/clean-native-caches.ps1`. It deletes only Gradle caches: any `.cxx` / `.gradle` /
`.kotlin` folder, plus `build` folders that sit next to a `build.gradle(.kts)`. JavaScript
`build` folders such as `node_modules/@expo/config/build` are left alone. Add `-ListOnly`
to preview without deleting. To delete a half-copied folder with long paths, use PowerShell 7:
`Remove-Item -LiteralPath <folder> -Recurse -Force`.

## Run it

**Just install the ready-made build on the running emulator:**

```bash
adb install -r release/InvoiceERP-1.0.1-emulator-x86_64.apk
```

`-r` upgrades in place and keeps the existing encrypted database.

**Start the emulator.** Use software graphics: on this PC the NVIDIA/Vulkan path crashes the emulator during boot.

```bash
"%LOCALAPPDATA%/Android/Sdk/emulator/emulator.exe" -avd Medium_Phone_API_37.0 -gpu swiftshader_indirect
```

In Android Studio, the equivalent is Device Manager → Edit → Graphics: **Software**.

| `cd android && gradlew.bat assembleRelease -x lintVitalAnalyzeRelease -x lintVitalRelease` | Release APK → `android/app/build/outputs/apk/release/app-release.apk`. The `-x lint…` flags are required: lint runs out of memory (Metaspace). Set `JAVA_HOME` to Android Studio's `jbr`. |
| `cd android && gradlew.bat assembleDebug` | Debug APK (needs Metro: `npx expo start --port 8081` + `adb reverse tcp:8081 tcp:8081`) |
| `npx expo run:android` | Debug build + install + Metro in one step (live reload) |
| `npx expo export --platform android` | Check the JS bundle builds |
| `npm run prebuild` | Regenerates `android/`. **This wipes the edits below; re-apply them afterwards** (`grep -rn "LOCAL EDIT" android` finds the signing and manifest ones). |
| `npm run build:apk` | EAS cloud build, `preview` profile: phone-ready APK in about 15 min. Needs `npx eas-cli login` (signing in on the website is not enough). `.easignore` keeps the local `android/` out of the upload so the cloud builds every CPU type and strips INTERNET. |

### Edits to re-apply after every `expo prebuild`

| File | Setting | Why |
| --- | --- | --- |
| `android/gradle.properties` | `reactNativeArchitectures=arm64-v8a,x86_64` | One APK for phones (arm64) and the emulator (x86_64). Emulator-only quick build: add `-PreactNativeArchitectures=x86_64` (~30 s vs ~24 min clean) |
| `android/app/build.gradle` | signing block from `~/.claude/skills/local-build-apk/templates/signing.gradle.txt` | Debug and release sign with the EAS phone key read from `credentials.json`, so local APKs update the phone's EAS-built app in place (debug key when the file is missing) |
| `android/app/src/release/AndroidManifest.xml` | removes INTERNET + ACCESS_NETWORK_STATE | Release APKs stay offline, like the EAS builds |
| `android/gradle.properties` | `expo.sqlite.useSQLCipher=true` | Without it the DB silently falls back to unencrypted SQLite |
| `android/local.properties` | `sdk.dir=C:/Users/<you>/AppData/Local/Android/Sdk` | Prebuild doesn't always write it |

### Versioning

The version lives in **`app-version.json`** (`version` + `versionCode`). `app.config.ts` reads it for
EAS builds, and **Settings** shows it at the bottom ("Invoice ERP 1.0.1 (build 2)"), so you can
tell which build a phone is running. **Bump `versionCode` before every build you hand out.** For
local Gradle builds, also update `versionCode` / `versionName` in `android/app/build.gradle`
(prebuild regenerates them from the config).

### Build for a real phone

**Development:** local Gradle, set up with the `/local-build-apk` skill ("Local-Build-apk",
`~/.claude/skills/local-build-apk/SKILL.md`; this project's record: `LOCAL_BUILD_APK/`).
Once `credentials.json` holds the EAS key (`npx eas-cli credentials -p android` → Download), the
`assembleRelease` command above makes one APK that installs on the emulator and updates the
phone's EAS-built app without losing data. Check it first with
`python -I ~/.claude/skills/local-build-apk/templates/verify_apk.py android/app/build/outputs/apk/release/app-release.apk --credentials credentials.json --package com.jiametric.invoiceerp`
(needs `RESULT OK`). **Back up `credentials.json` and `credentials/android/keystore.jks`
outside the project**: without them phones can never be updated again. Both are git- and EAS-ignored.

**Production:** `npm run build:apk` (EAS cloud, same key). Bump `versionCode` first.

## Environment configuration

None. The app is offline by design and needs no `.env` variables. The database key is created
on first launch and stored in the Android Keystore. It never leaves the device, so backups only
restore on the same device or install. The app-lock PIN is set by the owner on first open; only
its salted hash is stored (secure storage, never in the repo or in backups).
