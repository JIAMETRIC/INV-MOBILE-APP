# MOBILE_APP_CONVERSION — Tracking

Conversion of the Flask/pywebview desktop **Digital Invoice ERP** into a local-only,
Android-only **React Native + Expo** app, per [`invoice-app-plan.md`](../invoice-app-plan.md).
The project is the self-contained `INV-MOBILE-APP/` folder that holds this file (`..` = project root).
History: it started as `digital-invoice/mobile/`, became a standalone folder on 2026-10-21, and on
2026-10-22 (Prompt 30) became the **only** home of everything mobile. These topic docs, the plan
and the original requirements (`Barathy-Mobile-App-Tasks.txt`, this folder) now live here only;
`digital-invoice` keeps just a pointer. Earlier walkthrough entries that say "both copies synced"
predate that move.

## Rationale

| Spec | Why chosen | Alternatives / trade-offs |
|---|---|---|
| Expo SDK (newest stable) + CNG + `expo-dev-client` | Plan §2 mandates it; config plugin ecosystem for SQLCipher; `android/` regenerated by prebuild so it never rots. | Bare RN CLI — more control but manual Keystore/Gradle upkeep for SQLCipher; rejected. Flutter — rejected, plan fixes the stack. |
| `blockedPermissions` INTERNET only in **release EAS profile**, not in `app.json` base | Metro/DevMan need networking in dev; blocking globally makes development impossible (plan §3, §12). | Blocking in base + separate dev app.json — duplicate config drift risk; rejected. |
| **Integer paise** for all money (`BIGINT` columns, paisa amounts) | Desktop app stores REAL and double-rounds (2dp per tax line, then 0dp round-off); plan §12 flags floating-point totals as a pre-Phase-4 decision. Port now while schema is fresh. | Keep floats for byte-parity with desktop — rejected: plan explicitly wants integer maths. |
| **ISO-8601 `TEXT` dates** (`YYYY-MM-DD`) | Desktop stores `DD-MM-YYYY` strings and every query carries a CASE-based date rewrite hack (`invoice_repo.py:8-12`). Mobile schema drops the hack. | Mirror desktop format for easier import — rejected; sorting/filtering cost too high. |
| Invoice **status lifecycle** (draft/issued/partial/paid/void) as a column on `invoices` | Plan §7 status glyphs (● ◐ ○ ✕) require it; desktop only had `active` + a separate drafts table. Drafts remain a separate autosave table AND get a status. | Keep desktop active/deleted-only model — rejected, plan UI assumes lifecycle. |
| Party **snapshot** columns on invoice (denormalized) | Preserves desktop behaviour: invoices must not change when a client is edited later. | FK + JOIN — rejected for invoice immutability semantics. |
| SQLCipher via `expo-sqlite` `useSQLCipher` + key hex in `expo-secure-store`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY` | Plan §3 verbatim. Keystore-backed, device-bound. | App-side passphrase — weaker, and plan already specifies Keystore. |
| Keep desktop domain rules ported: GST flat 5%, TN state_code contains "33" → CGST+SGST 2.5/2.5 else IGST 5; round-off to whole rupee; amount-in-words Indian numbering | These are the business rules of the app (`record_service.py::_compute_taxes`, `number_to_words_indian`). | Redefining tax logic — out of scope; parity required. |
| Invoice numbering `{prefix}{seq:03d}` with `next_seq` in settings singleton + resync from MAX suffix of issued invoices | Port of `sync_next_invoice_sequence()`; atomic at issue time inside the same transaction. | Free-form numbers — rejected, breaks ledger ordering. |
| Re-implement missing desktop features (clients/products/payments CRUD routes were removed from the slimmed Flask backend but exist in schema) | The mobile app is a full replacement; schema + `models.py` DTOs are the spec. | Skip — would leave plan screens (Clients, Items) with no data path. |
| **Prompt 14 — GST removal:** drop tax_type, CGST/SGST/IGST (basis points + paise), taxable, HSN, GSTIN, state codes everywhere (schema, money core, repos, UI, PDF/XLSX, tests) | User decision: this business bills without GST. Round-off to whole rupee **kept** — it is a rupee-cash convention, not a GST artefact. Company **PAN kept** in settings — PAN is income-tax ID, not GST. | Keep the columns and hide them — rejected: user said "remove completely", and dead columns keep reviving UI bugs. |
| **Prompt 14 — Clients removal:** delete `clients` table, repo, screen, tab, and audit action; invoices carry a **free-text party snapshot** (name/address/city/pincode/mobile/email) typed on the invoice; payments key on `party_name` + invoice-id CSV | User-approved option; the snapshot preserves invoice immutability (editing a party never rewrites past invoices) without a second CRUD module. | Reuse party fields with an optional light contact list — deferred; user wants the module gone, can return as its own task. |
| **Prompt 14 — Clean rebuild migration:** `SCHEMA_VERSION = 2`; on any version mismatch, drop all tables child-first (incl. legacy `clients`) inside one transaction and recreate v2 | Only test data exists on any device, so a data-migration path would be untestable dead code. Wipe is provable and covered by a dedicated schema-guard integration test. | Versioned ALTER migrations — rejected: cost without benefit while pre-release. |
| **Prompt 15 — Items → Products rename:** `items` table becomes `products` with columns Name / Size / Price / Stock / Sold / Avl-Stock only; one row per **(name, size)** pair, `UNIQUE(name COLLATE NOCASE, size COLLATE NOCASE)` | User decision; garment catalog is naturally name×size and Sold/Avl must be per-size. | One row per name with a size list — rejected: Sold/Avl aggregation would need JSON or a child table. |
| **Prompt 15 — Sold is computed, never stored:** `sold = Σ qty` over `invoice_items` joined to non-void `invoices`; `avl = stock − sold` (can go negative — overselling must stay visible) | Stored counters drift on edits/voids/deletes; the correlated subquery is single-source-of-truth and matches the desktop's computed-stock habit. Avl negative renders in `accentDeep` instead of being clamped. | Trigger-maintained counters — rejected: invisible state, hard to test in the headless harness. |
| **Prompt 15 — style_code dropped completely** (also `uom`, `category`, `hsn`-era fields, reorder_qty): invoice lines reference `product_id` (nullable FK) and carry `description` (e.g. "Hoodie - L"); free lines keep `product_id = NULL` | User-approved: table must show exactly the six requested columns. Nullable FK preserves invoice history when a product row is deleted (`deleteProduct` nulls references first). | Keep style code as an optional tag — rejected per explicit user choice. |
| **Prompt 15 — Seed catalog:** 12 names × 5 sizes (S–XXL) = 60 rows inserted idempotently (`INSERT OR IGNORE`) at schema build, plus a count-based self-heal in `listProducts` | Pre-release DBs are wiped anyway, so seeding is free UX; the self-heal also covers the web-tier rebuild edge below. | Settings-driven seed list — deferred; names are hard-coded in `PRODUCT_SEED_NAMES`. |

Android never reproduced it (harness 14/14). | Wipe OPFS on every schema bump — rejected: breaks the no-migration contract on real devices. |
| **Prompt 16 — Restock ledger:** new `restocks` table (kind `restock`/`edit`, delta, stock_after, unit_paise, note, created_at); `products.stock_qty` stays the running balance and `Stock = Σ delta` is a tested invariant | User chose ＋Restock per product + full history. Recording editor corrections as `edit` deltas keeps the ledger complete, so a later audit of "why is stock 55" has one answer source. ON DELETE CASCADE + delete test. | Stock as pure Σ restocks minus sales (no balance column) — rejected: Sold already joins invoices; a second aggregation chain would slow every row. Audit-log-only restocks — rejected: user explicitly asked for viewable history. |

## Mobile schema (src/data/schema.ts, `PRAGMA user_version` migrations)

**Current: v4 (Prompt 16).** v3/v2/v1 below are kept for history; on any version mismatch the DB
is wiped child-first and rebuilt at v4 (clean-rebuild decision — only test data existed).
v4 additionally self-heals when `user_version` lies about the schema (probe now requires both
`products` and `restocks` in `sqlite_master`; see Rationale).

All money columns are **integer paise** (`INTEGER` in SQLite, 64-bit). Dates ISO `TEXT`.

Migrations read the current version as `getFirstAsync('PRAGMA user_version')` — the value arrives under column `user_version` (there is no `v` alias), and `dbCore.ts` reads it as such (integration-verified; reading a non-existent `v` key would silently re-run migration steps on every start).

### v4 (restock ledger, current)

- `restocks` — id, `product_id` FK → products(id) **ON DELETE CASCADE**, `kind` CHECK('restock','edit'), `delta` REAL (signed stock movement), `stock_after` REAL (balance snapshot), `unit_paise` INT (effective price at time), `note` TEXT, `created_at`. Index `idx_restocks_product(product_id, id)`.
- Invariant (integration-tested): `products.stock_qty = Σ restocks.delta` — restock receipts (`restockProduct`), editor Stock overwrites (`upsertProduct`, delta vs previous), and new-product opening stock (insert path, non-zero only) all append rows.
- `invoice_items.product_id` stays nullable; **Sold/Avl semantics unchanged** — Avl reflects restocks immediately because it reads `stock_qty`.
- Drop list grows to: `backup_logs, audit_logs, drafts, payments, invoice_items, invoices, restocks, products, items, clients, meta`. Lie-probe now asserts both `products` and `restocks` exist in `sqlite_master`.
- Audit union gains `product.restock`; UI: Products editor Restock panel + Stock history list (see Layout).

### v3 (after Items → Products rename)

- `products` — replaces `items`: id, sl_no, `name` TEXT, `size` TEXT (`''` = No size), `unit_paise` INT (Price), `stock_qty` REAL (Stock), created_at/updated_at. **No style_code / uom / category / reorder_qty.** Unique index `uq_products_name_size ON (name COLLATE NOCASE, size COLLATE NOCASE)`; index on name. `Sold`/`Avl-Stock` are **not columns** — computed in `productsRepo.ts` `SELECT_ROW` via a correlated subquery (`SUM(li.qty)` over `invoice_items` JOIN `invoices` `WHERE i.status != 'void'` keyed on `li.product_id = products.id`).
- Seed: `PRODUCT_SEED_NAMES` (Round Neck T-Shirt - IMP, Round Neck T-Shirt, Drop Shoulder T-Shirt, Acid Wash T-Shirt, Polo T-Shirt - IMP, Polo T-Shirt, Hoodie, Track Pant - IMP, Track Pant Cotton, Track Pant Sports, Full Hand T-Shirt - IMP, Full Hand T-Shirt) × `PRODUCT_SIZES` (S, M, L, XL, XXL) → `productSeedSql()` 60 rows (price/stock 0), run inside `createSchema` and again by `ensureSeeded` self-heal when `COUNT(*)=0`.
- `invoice_items` — `style_code`/`uom` dropped; gains `product_id INTEGER REFERENCES products(id)` (nullable; NULL = free-text line) + index `idx_invoice_items_product`. Columns now: id, invoice_id FK, sno, product_id, description, qty, unit_paise, line_paise, restock_lot.
- `invoices`, `meta`, `payments`, `drafts`, `audit_logs`, `backup_logs` — unchanged from v2 (audit action `item.upsert` renamed `product.upsert` in the TS union only).
- Drop list for clean rebuild: `backup_logs, audit_logs, drafts, payments, invoice_items, invoices, products, items, clients, meta` (legacy `items`/`clients` still wiped for old DBs; v4 inserts `restocks` before `products`).

### v2 (after GST + Clients removal — historical)

- `meta` — singleton `id=1`: company name/subtitle/address/city/pincode/**pan**/contact/email (state_code, gstin dropped), bank_name/branch/ac_no/ifsc/upi_id, `invoice_prefix` (default `PRE-`), `next_seq`, logo flags, updated_at.
- ~~`clients`~~ — **table dropped**; party fields live on the invoice row.
- `items` — id, sl_no, style_code UNIQUE, product_name, category, uom, unit_paise, qty REAL, reorder_qty, timestamps (hsn_code dropped).
- `invoices` — id, invoice_no UNIQUE, status, invoice_date/due_date ISO, party snapshot `party_name/address/city/pincode/mobile/email` (client_id, party_state_code/gstin/pan dropped), gross_paise, discount_percent, discount_paise, round_off_paise, total_paise, amount_in_words, upi_id, notes, has_shipping, ship_name/address/city/pincode (ship_state_code/gstin dropped), timestamps. No tax_type / *_bp / tax paise / taxable columns.
- `invoice_items` — as v1 minus `hsn`.
- `payments` — as v1 minus `client_id`; keyed on free-text `party_name` + invoice-id CSV (delimiter-safe LIKE retained).
- `drafts` / `audit_logs` / `backup_logs` — unchanged (audit action `client.upsert` removed from the TS union).
- Indexes mirror the surviving columns: invoices(invoice_no, invoice_date, party_name, status), invoice_items(invoice_id), items(style_code), payments(payment_date), audit(created_at).

### v1 (original conversion, pre-Prompt 14 — historical)

- `meta` — singleton `id=1`: company … state_code/gstin/pan … (all v1 fields).
- `clients` — id, sl_no, party_name UNIQUE, address, city, pincode, state_code, gstin, pan, contact_person, mobile, email, transport, remarks, created_at, updated_at.
- `items` — id, sl_no, style_code UNIQUE, product_name, category, hsn_code (default '6103'), uom, unit_paise, opening_paise? no: `unit_paise`, stock_qty REAL kept as `qty REAL` (quantities are not money), reorder_qty, created_at, updated_at.
- `invoices` — id, invoice_no UNIQUE, status CHECK(draft|issued|partial|paid|void), invoice_date ISO, due_date ISO, client_id FK (nullable, snapshot kept anyway), party_* snapshot, subtotal_paise, discount_percent INT, discount_paise, taxable_paise, tax splits (cgst/sgst/igst percent x10? stored as INTEGER percent + paise amounts), round_off_paise, total_paise, tax_type intra|inter, amount_in_words, notes, ship_* columns, created_at, updated_at.
- `invoice_items` — id, invoice_id FK CASCADE, sno, style_code, description, hsn, qty REAL, uom, unit_paise, line_paise, restock_lot nullable.

Indexes mirror desktop: invoices(invoice_no, invoice_date, party_name, status), invoice_items(invoice_id), clients(party_name), items(style_code), payments(client_id, payment_date), audit(created_at).

## Export specs

- PDF: HTML template reusing `gray` token values, base64 `@font-face`, A4 + Letter, `expo-print.printToFileAsync`, share via `expo-sharing`. Content mirrors desktop Courier grid letterhead: logo/company/bank block, party + ship-to, line table, round-off, amount-in-words, UPI QR image, signature. (v1 had GSTIN + 8-col table with HSN + GST summary; removed in Prompt 14 — line table is 7 cols, totals show Gross/Discount/Round off/TOTAL only. Prompt 15: style_code column dropped → line table is **# / ITEM / QTY / RATE / AMOUNT** (5 cols).)
- XLSX: **in-house synchronous writer** (`src/export/xlsxWriter.ts`, zero dependencies — see "Why no exceljs" below). Batched SQLite reads, row cap 50k/sheet. Sheets: single invoice register, consolidated `Invoices_Register` + `All_Line_Items` (Prompt 15: Invoice No/Sno/Item/Qty/Rate/Amount — Style/UOM columns gone), products (`exportProductsXlsx` → sheet `Products`, columns Name/Size/Price/Stock/Sold/Avl-Stock with the same computed subqueries, file `products_<ts>.xlsx`). HSN and tax columns removed in Prompt 14; register columns are Invoice No/Date/Status/Party/Round Off/Total. Layout per sheet: bold frozen header row, explicit column widths, money columns rendered `#,##0.00` right-aligned via `cellXfs` index 2, strings inline (`t="inlineStr"`, no `sharedStrings` part).
- Every generated file lands in `Documents/<Exports|Invoices|Backups>/` through the shared `docsDir()` helper, which **must** call `dir.create({ intermediates: true, idempotent: true })` — plain `create()` throws `Unable to create file or directory: it already exists`, which silently made the second and every later export of a session fail (Prompt 19).
- Backup: in-app encrypted DB file export/import (`DocumentPicker` → copy `.db`, restore requires confirm + pre-import snapshot) — replaces desktop zip packages + EOD auto-backup (EOD retained: on first open per day, snapshot into app storage, prune to 7).

## Packaging / build config

Web preview tier (dev-only, not shipped): `react-native-web` + expo-sqlite's wa-sqlite/OPFS driver. Requires `resolver.assetExts` += `wasm`, COOP/COEP `web.headers`, platform files `dbKey.web.ts`/`db.web.ts` (split core into `dbCore.ts` — Metro self-resolves `./db` inside `db.web.ts`), and `src/ui/alert.ts` (RNW `Alert.alert` is a no-op). Native guarantees (SQLCipher, exclusive tx) exist only on Android. Web gotcha found in Prompt 15: OPFS can persist `PRAGMA user_version` from a migration whose DDL never landed, so `migrate()` probes `sqlite_master` for `products` and forces a rebuild when the version lies; `DB migration failed` is logged to console instead of swallowed.

| Variant | Result on device |
| --- | --- |
| patched Promise left in place | write succeeds, then every later promise rejects with `RangeError: Maximum call stack size exceeded` — share sheet never shows |

ever crosses the boundary. `npm run test:xlsx` guards its ZIP/OOXML structure; `openpyxl` (host
